# Curiosity coverage bridge: prospective runtime forecast

Status: prospective planning method, written before the new engineering outputs. This implements the resource rule in [the bridge plan](curiosity-coverage-bridge-v1-plan.md). It grants no compute admission and uses no behavioral effects or answer categories. A failed forecast will not trigger a smaller panel, replacement cohort, new dose, longer deadline, or retry.

## Bound inputs and generation estimate

Bind the closed C admission2 parent, archive, all three child manifests, all 135 generation-evidence files, and the three cloud profiles. Reconstruct every original arm/cohort from manifest assignments and exact evidence trial-ID order; inspect only timing and input metadata. Historical `condition.elapsed_seconds` is a generation timer. Historical `execution_seconds − sum(generation timers)` is a mixed upper envelope for receipts, I/O and other execution overhead, **not** a measured receipt component. Captured-pass `batch_seconds` is not the paired receipt cost and will not be used.

Bind the new engineering manifest and independent context audit, raw calls 0–15 and arrays, receipts 10–15 and arrays, collector start/summary, environment, cloud-finished and local launch-outcome. The fixed matched timing pairs are old baseline versus new baseline and old C− versus new record C−, on cohorts 0 and 3. Let `R = max(1, all four new/old generation ratios)`. Let `F = max(1, full-C/record-C generation ratio on each of those two cohorts)`. For every one of the 261 prospective generation calls, use its corresponding original arm/cohort time multiplied by `R`, and additionally by `F` for a full-prefix schedule. Baseline has one call; each of the other fourteen original arms has a record and a full-prefix call. No control is assigned the C− absolute runtime.

The new generation timer excludes initial `StateBackend.prepare`, initial mask/unit setup, and post-call checks. Preserve that scope. Independently compute the new collector's end-to-end elapsed time minus **all sixteen** generation timers, including deliberate faults. This is another mixed-overhead envelope. For each scientific worker reserve the larger of (a) its historical mixed envelope scaled from 45 to 87 calls and (b) the new mixed envelope scaled from 16 to 87 calls. This deliberately overlaps the explicit allowances below; it is a conservative planning reserve, not a decomposition of measured costs.

## Receipts, persistence and export

Reconstruct every one of the 4,176 logical choice dispositions, assuming every choice could require a non-stop receipt. Preserve the original cross-cohort regrouping in each worker's assigned order, in groups of at most 32: maximum 49, 43 and 40 receipt batches. Do not use the engineering cohort-subset grouping as the scientific grouping. Each slot's possible report/repeat/pattern token lengths come from the bound original input-only receipt inventory. The largest possible length in a batch determines its padded width.

Use complete new measured paired baseline-plus-capture receipt forwards. Scale each measured active-row cost to a proposed batch by its row-count ratio and by `max(1, proposed padded width / measured padded width)^2`; take the largest resulting prediction across the available measurements. This squared-width/per-row rule is a conservative **extrapolation assumption**, not a measured upper bound. Apply the same rule to measured receipt parsing time. If no actual selected receipt forward was measured, the cost decomposition is unavailable and the forecast fails. A synthetic one-token assistant receipt inventory is input-only; record the fresh-rendering/template assumption and check observed valid receipt widths against it.

Generation artifact bytes are extrapolated separately for baseline, record and full schedules: take the maximum of each matching timing sample's bytes multiplied by `max(1, predicted generation seconds / sample generation seconds)`. Receipt bytes use the maximum measured bytes scaled by row count and a linear padded-width ratio. These are storage estimates, not guaranteed byte limits. Apply the largest measured persistence seconds per byte, with a per-call measured-time floor. Persistence serialization times are measured only by the collector, not independently recoverable from saved bytes.

Reserve checkpoint time from the larger of measured time per artifact-byte and the largest observed commit duration per prospective checkpoint; add one largest-observed-commit allowance for the unmeasured final commit. Scale local export elapsed time by predicted versus observed artifact bytes. This export timer includes download **and local coverage/hash processing**; it is not a network-only measurement. All extrapolations remain explicit. Retain a separate **$10 storage reserve** without asserting an unverified storage price.

## Decision and limits

Add the largest observed model-loading time and measured non-loading startup/lifecycle overhead. Apply a 25% margin to the execution estimate including generation, the mixed-overhead reserve, receipts, persistence, checkpoints and export. Every worker must fit the fixed 19,000-second startup-inclusive deadline. Three workers plus their 120-second teardown reserves imply the fixed maximum compute liability of $79.9460736, below the $80 compute ceiling. The $10 storage reserve is separate. The helper does not replace the global allowance and stopped-app admission check.

Missing, inconsistent, nonfinite or incomplete timing decomposition produces an unavailable/failed forecast. All input file hashes and all arithmetic terms are exported. Neither measured representative runs nor these explicit extrapolations guarantee that every unobserved control trajectory, an all-cap run, or a different receipt layout will finish. The main scientific panel remains conditional on independent review and a separate frozen admission.
