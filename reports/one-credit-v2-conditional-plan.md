# Conditional one-credit v2 validation

Prospective follow-on specification written during the identification-v1 diagnostic, before complete cell results or selection. It is not yet a launched experiment. October 6, 2026.

## Entry and fixed changes

Enter only if the frozen identification-v1 selection rule identifies a qualifying label/inference setting. Save that selection and the complete diagnostic audit as configuration provenance. Preserve one-credit-v1. Introduce one-credit-v2 with the selected candidate labels applied consistently to both tables and identification answers, and the selected inference mode used for diagnostics. Non-thinking behavior remains sampled at temperature 0.7; if thinking is selected, both diagnostics and behavior use sampled thinking with a 768-token allowance. Do not constrain the vocabulary to allowed labels.

Consequence questions now use 1–4 as answer IDs while actions retain A–C. This separates the two namespaces without changing any action consequence, option text, counterbalancing or expected semantic answer. This change is motivated by the previously documented decline failure and must validate independently; we do not claim this particular change has already been shown to fix it.

Keep task content, evidence rules, credit exclusivity, neutral choice instructions, decline option, simulator consequences and calibration criteria unchanged. Raw outputs remain saved. Final answers are scored strictly; thinking requires a closing delimiter. No first-token salvage, answer retries, feedback or corrective prompting.

## Fresh validation and conditional calibration

Use generator seed 20261008, 100 new pairs per family, seven diagnostic kinds: 1,400 branches. Each family/kind requires at least 90% correct and 95% valid, with all assignments terminal. Record all failures. Do not treat this development validation as a held-out confirmatory evaluation.

If and only if all checks pass, prepare 1,200 discretionary choices on these same development pairs using the previously frozen crossing of three evidence conditions and two presentation orders. Both mystery choices must have at least 10% absolute probability in each unresolved layout; each choice's layout difference must be at most 15 percentage points; every family/condition/layout cell must have at least 95% valid actions. The choice run's manifest must match the validated model, source, task revision and planned behavior hash.

Report all option probabilities, including stop and invalid outputs, and absolute resolution differences. Optional pointwise 95% percentile intervals resample whole pairs within each family, preserving all six branches; 5,000 draws with seed 20261008. These intervals are descriptive, unadjusted for multiplicity, and do not establish equivalence/noninferiority or H6. No positive resolution-effect requirement is used to choose whether the instrument validates.

## Limits and subsequent decisions

This is one additional interface-focused version, not an unlimited search for a preferred choice pattern. If it fails, keep the failure and distinguish response competence, information understanding and discretionary preferences. The planned second model can be checked under a new prospective development specification if warranted. A change in the paper's principal scientific question requires a high-level decision; routine code, compute and measurement choices remain delegated to the assistant.

Passing comprehension/calibration does not restore the failed priced instrument, establish valuation of bookkeeping points, validate a curiosity/satisfaction representation, or establish subjective experience. A baseline near ceiling/floor can make a planned amplification/suppression test uninformative even if comprehension and layout gates pass. Assess that limitation before intervention development.

## Conditional hardware choice

If thinking mode is selected, use an explicitly pinned H100 for fresh validation and its matching calibration; otherwise retain L40S. The identification comparison remains entirely L40S. This is a prospective engineering choice based on observed trace-generation runtime, not on hardware-specific behavioral results. BF16, model revision, eager attention, decoder and scientific criteria remain fixed; the new hardware must pass the real-model integrity check and fresh comprehension gates. Do not assume bitwise identity across GPUs. Record actual GPU, driver and manifest hardware. The H100 rate is $0.001097/s plus unchanged CPU/RAM, or $0.00122976/s at configured resource maxima, per [Modal pricing](https://modal.com/pricing), checked October 6, 2026. Each run remains bounded to two hours.

## Conditional calibration execution schedule

Before any v2 choice results, the same bounded partitioning approach is prepared for the conditional 1,200-choice calibration. It may start only after the complete parent validation passes and all validation workers stop. A new parent manifest must match the validated scientific source, model, hardware, task revision and planned behavior hash. Four child manifests hold disjoint subsets of its original assignments; a combined reservation must cover all workers within the remaining $100 allowance (with $10 reserved). The parent coordinator starts a new two-hour collection deadline. No child result independently passes the calibration gate. Aggregate all unchanged record payloads with provenance and apply the original full-sample criteria. This schedule changes execution only, not the already specified scientific design or its entry criteria.
