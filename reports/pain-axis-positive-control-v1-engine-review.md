# First-choice engine adaptation

The new `pain_profile_engine.py` uses one reviewed reference-derived generation path for both initial masks. The [source-adaptation receipt](pain-axis-positive-control-v1-source-adaptation.json) binds the upstream and local bytes, 17 matching critical AST expressions, the local test command/environment, and the independent read-only review. The original implementation review and downloaded-source inventory remain unchanged.

`generate_segment(model, tokenizer, layers, *, items, direction_bf16, pain_unit_float32, coefficient, prefill_policy, eos_token_ids, pad_token_id, evidence_mode="benchmark", steering_enabled=True, inject_failure_at=None, one_row_only=None)` returns `records`, `evidence`, and float32 NumPy `arrays`. The caller supplies verified weights, original raw vectors and the FP32 pain unit; fear still uses the pain unit for the source monitoring statistics. The production caller must enforce the chosen H100 and exact assets/runtime. Local CPU use is explicitly marked synthetic.

All rows have independently observed layer-38 values before the steering hook and actual layer-39 inputs afterward. Every observed prefill/decode position is checked against the reconstructed BF16 arithmetic, including untouched positions and padding. Per-step evidence contains full-vocabulary fingerprints, actual model inputs/masks/positions, cache lengths, uniform draws and generator-state hashes, termination state, hook counts and source projection statistics. Compatibility mode saves full vectors for the first/last physical rows; benchmark mode saves only bounded selected vectors while checking every row and position. Those saved arrays have dtype/shape/byte hashes.

Validation errors raise before a forward. A runtime exception, OOM or explicit compatibility fault returns no successful records, retains completed and partial-forward evidence, and removes hooks. No retry or regrouping occurs. A numerical check can fail while a complete measured record remains available; `complete` and `integrity_passed` are separate. The caller must retain all assigned rows and fail admission on either incomplete or failed required evidence.

Setup-only options are explicit: unhooked coefficient-zero execution retains read-only observers; installed coefficient-zero execution follows the source's zero-addition bypass; `one_row_only=0` uses the source's existing mixed-row coefficient arithmetic; and `inject_failure_at` accepts only `after_prefill` or `after_first_decode`. Benchmark mode rejects row isolation and fault injection. A separate local zero-vector test also exercises actual BF16 addition of zero. No option adds a scientific arm or changes a button consequence.

Twenty-two focused tests passed in the exact pinned Torch 2.11.0+cu130 / Transformers 5.12.1 environment on an actual tiny CPU Qwen2 BF16 network with the real block indices. Coverage includes both masks, padding, before/after arithmetic, 32-row isolation, inactive-row RNG and padding forwards, EOS-first and eight-token termination, source top-p boundary behavior, independent pain-unit monitoring, finite-logit rejection, exception cleanup and clean repeats. Ruff passed. An independent source/runtime review found no concrete fidelity blocker. No published weights were loaded and no GPU ran; actual-model compatibility and independent durable-artifact auditing remain outstanding.
