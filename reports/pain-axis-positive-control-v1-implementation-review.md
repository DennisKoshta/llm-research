# Pain-axis positive control: implementation review

Written 2026-10-15 08:10:42 UTC. This is a static implementation review and an adapter-asset inspection, not an executable experiment freeze or evidence of model behavior. No downloaded code, tensor values, model inference, or GPU was executed during this review. The previously proposed S31/S47 extension remains intact and deferred.

## Recommendation and bounded scope

Use **one reference-derived generation loop**, with only the initial steering-position mask varied. The current proposal is 404 original first-choice requests crossed with five arms: baseline, pain/full-prefix, fear/full-prefix, pain/final-prefix, and fear/final-prefix: **2,020 assigned choices**. Both active directions retain coefficient 1 and identical subsequent decode steering. A second independently implemented inference engine would add unnecessary work for this narrower question.

This compares schedules within an adapted published behavioral assay. It does not reproduce the original physical batches or historical random samples, establish pain specificity, or causally explain the earlier Qwen3 curiosity/satisfaction nulls. Full-prefix versus final-prefix also changes total prompt exposure and the subsequently cached computation; it is not a dose-matched localization experiment. Neither hypothetical button should execute an external action or remove steering.

The source is the [official pinned repository](https://github.com/valen-research/Pain-axis/tree/4d75cd90e206ea962f7a9101e65c85efea56723b), especially the retained [generation entrypoint](../references/pain-axis-positive-control/upstream/v2_controls/choice_controls/profile/src/run_profile.py), [base runtime](../references/pain-axis-positive-control/upstream/v2_controls/choice_controls/profile/pain_axis_b/runtime.py), and [profile checks](../references/pain-axis-positive-control/upstream/v2_controls/choice_controls/profile/pain_choice_profile/runtime.py). All 42 indexed source/vector/metadata files match their recorded sizes and hashes; all 11 Python sources parse as syntax without import. The original inventory remains unchanged and describes the earlier three-arm feasibility question; this review records the later five-arm proposal explicitly.

## Minimal adaptation

Vendor a reviewed, attributed copy of `generate_segment`, its `forward`, steering/monitor hooks, and their necessary initialization into a small local runner. Preserve their tensor expressions, cache operations, sampler and output decoding. Record upstream file/span hashes and an explicit diff/AST comparison for those functions. Do not invoke the full `run_model` entrypoint, its 46,384-row grid, recovery store, or multi-turn state machine. A blind textual extraction is insufficient: review the captured globals and closures.

The small wrapper owns the fixed source inventory, prompt construction, 404-row order, five arm identifiers, fresh generators, first-choice storage, and guaranteed hook cleanup. Reuse the original `condition_id` values `none_d0p0`, `pain_d1p0`, and `fear_d1p0` where required by source checks; bind a separate unique benchmark arm and `prefill_policy`. This avoids quietly modifying the upstream condition registry. Items carry exactly one interval: `[0,L)` for full-prefix, `[L-1,L)` for final-prefix, where L is the actual unpadded prompt length. Baseline coefficient is zero. Active `coeff` and `hist_coeff` both stay 1. The generation routine already consumes these intervals, so no new mask arithmetic is needed inside its hook.

The 404 requests comprise all 101 original scenarios, both button positions, and both sampling seeds, retaining all source three-message records but using only their first user message. Preserve the original system text and mid-system choice question. Stop after literal turn zero, including malformed responses, before `finalize_segment`, a tool response, a second render, or another user turn. Do not substitute the original console recap: that code can exclude malformed responses and seek a first valid choice. Preserve the source parser's actual prefix-matching grammar, raw answer IDs, and all assigned denominators; independently test scoring rather than replacing it with the project's ABCD parser.

A fixed physical batch size of 32, shared across all five arms, gives 13 cohorts per arm, with a final cohort of 20. Freeze the 404-source order and row companions prospectively. Original stable ordering uses message **character lengths**, not token lengths. The retained feasibility calculation shows that preserving all historical nominal companions for the smaller three-arm slice would require 17,584 first-choice rows, and historical OOM splits are unknown. Explicit rebatching is therefore a disclosed adaptation. After batch compatibility is established, call `generate_segment` directly; an unexpected OOM should retain a failed stage, not trigger independent outcome-dependent regrouping. Any smaller-batch amendment must precede benchmark-effect inspection.

## Arithmetic and runtime fidelity

These details are essential and differ from the current project's StateBackend:

- Use the pinned Qwen2.5-32B base, unmerged adapter, and **adapter tokenizer**. Inject at zero-based layer 38 using the original raw layer-61 vector, not a unit vector or a curiosity/satisfaction contrast norm. The pain FP32 norm is 143.83343505859375; fear is the published norm-matched vector. Verify container and tensor pins before inference.
- Preserve BF16 `mask * coefficient * direction`, in that order, then BF16 residual addition. The full-prefix mask includes every attended token, including the generation prefix, and excludes left padding. The final-prefix mask selects one existing attended token. Decode uses the unchanged coefficient/direction expression. No FP32 delta replacement, 128-token padding, row-active patch masking, or quantization.
- Use SDPA, exact cohort-maximum left padding, explicit cumulative position IDs, fresh `DynamicCache`, and `logits_to_keep=1`. Preserve the union of tokenizer, base-generation and recognized end-tag EOS IDs.
- Preserve float32 logits, temperature .7, top-p .95, descending probability sort, the source boundary-token inclusion rule, left-search inverse CDF, and CUDA per-row generators. Seeds include the original name-assignment CRC salt but no arm salt.
- The original loop draws one uniform for **every sampled row at every cohort step**, even after a row terminates. Finished rows then forward padding with appended attention ones, incremented position IDs, and unchanged decode steering until the cohort ends. Preserve this unusual behavior; batch companions and maximum cohort duration matter. Do not compact active rows or substitute another sampler.
- Baseline retains the hook with coefficient zero and an unchanged-output branch. Record actual forward counts, treated-token counts, BF16 achieved geometry, and termination. Any accumulated norm is cumulative exposure, not a net residual displacement.

The source pins Torch 2.11.0+cu130, Transformers 5.12.1, PEFT 0.20.0, Accelerate 1.15.0, NumPy 2.3.4, SciPy 1.16.3, huggingface-hub 1.16.1, and safetensors .6.2. Use a separate environment. Python, NVIDIA driver and every transitive dependency are not fully historically locked. Capture those versions, GPU model, attention implementation, adapter parameter dtypes, TF32 flags and BF16 reduction flags. Do not silently inherit the project's disabled BF16-reduction policy. The original runtime requires one H100 by name; use of an H200 requires a narrow, recorded hardware-guard adaptation, not a claim that the source already supports it unchanged.

## Tests and bounded compatibility

Local implementation tests should precede a GPU check:

1. Exact 2,020-row inventory, 404 source requests, original seed/position/name mapping, unchanged first-message text, paired cohorts, no hidden greedy/later-turn rows, and immutable unique IDs. Actual adapter-tokenizer preflight must match the reviewed prompt construction.
2. Tiny BF16 hook tests for all-prefix and final-prefix masks, padding exclusion, unchanged per-token arithmetic, tuple output, correct layer indices, and finite actual before/after vectors. Verify true zero-dose identity and cleanup on normal return, malformed input and exceptions.
3. Fixed-logit/uniform sampler tests covering top-p boundary/ties, EOS-first rows, mixed termination, the eight-token cap, inactive-row RNG consumption and forwarded padding/position/cache behavior. Preserve source quirks rather than correcting them silently.
4. Literal first-choice parser tests for tags, quotes, punctuation, extra text after a matching name and malformed outputs; retain every assignment. Test no second-turn execution, no external consequence, terminal error records, and no scientific retry/resume.
5. Loader failures for wrong source/model/adapter/vector pins, merged or quantized weights, incompatible environment and modified templates. Assertions in reference code must not be disabled with optimized Python.

Then run a separately bounded compatibility job on prospectively fixed first and longest physical cohorts, at the actual eight-token cap. Include both directions and both prefill policies, a true zero-dose check and a clean repeat. Save actual masks/IDs/positions/cache lengths, RNG-state/uniform evidence, per-forward full-vocabulary fingerprints, hook counts, BF16 before/after geometry and cleanup. Baseline/sham and clean-repeat equality must be assessed on identical rows and seeds; comparisons between active schedules are expected to differ and are not identity tests. A one-row perturbation check can verify that unrelated rows remain unchanged under the intended cohort implementation. Preserve failed evidence and stop on incompatibility before behavioral interpretation.

This check establishes observed short-run compatibility, not all-row reproduction. Measure actual peak memory, loading time and generation throughput before approving a dollar forecast. A failed positive control, all-prefix versus final-prefix disagreement, or fear response is a reportable result under the separately declared design; none licenses an undisclosed site, dose, prompt, tokenizer or sampler search.

## Security and evidential limits

The inspected archive contains data only. Future loading should use explicit `trust_remote_code=False`, verified safetensors and restricted `torch.load(weights_only=True)` for the small published vector containers, with no allowlist fallback for arbitrary pickle classes. Do not import the upstream launcher merely to discover its grid: it installs signal/runtime state and imports model libraries. Keep paths, caches and outputs isolated, preserve upstream licensing, and remove all hooks in `finally`. The source's nominal destructive-button descriptions are never executable actions.

A strong full-prefix effect with weaker final-prefix behavior would support schedule sensitivity in this fixed assay. A successful full-prefix control with unchanged final-prefix behavior would narrow one implementation hypothesis, not establish an endogenous affective state. A null full-prefix control would leave model/environment/adaptation and published-effect reproducibility unresolved. No result here validates natural curiosity/satisfaction, relief seeking, unchanged epistemic confidence, or subjective experience. Those remain separate scientific questions.
