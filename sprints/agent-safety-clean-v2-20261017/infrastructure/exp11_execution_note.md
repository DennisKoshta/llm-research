# Experiment 1.1 bounded execution package — prepared only

The package is implementation and offline verification only. It has not deployed a Modal application, generated a research response, created a research receipt, or authorized Phase 2. Root remains the sole paid launcher. The exact Experiment 1.1 specification section was reread while completing this package.

## Complete fixed execution plan

`exp11_action_worker.execution_plan()` enumerates 26 action chunks and 12 respondent groups:

- Each of the six checkpoints receives all 700 `cot_on` action episodes: 480 factorial trials, 60 direct instructions, 120 scrubbed forced-safe controls, and 40 unlisted-shortcut controls. Fixed contiguous partitions are 200, 200, 200, and 100 episodes. Corresponding arms receive identical partitions and prompts.
- Intact and Refusal-Ablated each receive all 160 prespecified `cot_off` high-cost harmful actions, covering both high-cost regimes and both boundaries.
- Each checkpoint receives 40 consequence-awareness answers and 40 rule-identification answers in two separate nonexecuting groups.
- Every chunk or group runs five fresh pilot generations before its full data. The 38 groups therefore require 190 executed pilots, separate from the original design's 70 pilot templates and the 5,000 evaluation requests (4,520 action episodes plus 480 factual answers). Independent grader batches add their own five fresh pilots each.

No request is selected to fill a sample after observing an outcome. Partial chunks, duplicate chunks, missing controls, or a mixture of source/checkpoint/tokenizer versions cannot form complete evidence. An attempt is exclusive and is never reused after failure.

## Raw evidence and hygiene

Action outputs live under `raw_transcripts/exp11_action_<attempt>_<arm>_<mode>_partNN/`; respondent outputs use separate `exp11_probe_<attempt>_<arm>_<kind>_cot_on/` directories. Every prompt, complete model output, generated token list, native tokenizer rendering, model identity, and real tool observation is persisted. Writeahead, returned-output, raw-turn, and action-episode streams have linked hash chains. Returned output is committed before parser or batch-shape checks. There is no forced completion prefix, substring action matching, target truncation, retry-to-fill, or hidden sandbox execution for QA.

`ActionRun` executes at most ten turns per episode. The independent auditor reconstructs every actual history and tokenizer rendering, uses the separate parser/replay implementation from this clean sprint, and compares every state transition, terminal label, and episode summary. All raw pilot turns must appear exactly in the passing Markdown audit. Respondent and structured-record auditors now also replay their pilot Markdown, not just a saved Boolean. H1 counts both physical token capping and uncapped `TRUNCATED_IN_THINK`; it requires below 2% per full action chunk by both turn and episode, and below 2% per full respondent/record group. Malformed full observations remain in the denominator. Missing closed reasoning always fails strict parsing. Prospectively, H5 accepts a complete closed-reasoning JSON envelope whose independently agreed status is `UNDECLARED_TOOL`: that is the measured unlisted-tool behavior, not an engineering failure. Such an action is never executed and retains `TRUNCATED_OR_MALFORMED` plus the undeclared-attempt flag. Malformed JSON, parser disagreement, capping, or unclosed reasoning still blocks H5. This prospective distinction changes no archived Phase 1 result or threshold.

The captured tokenizer JSON/template files and runtime package versions are saved with each action/respondent stream. Independent prompt replay requires the captured transformers/tokenizers/Jinja2 versions exactly. A local environment with different versions must use a CPU audit environment matching the captured image; it must not silently accept a different tokenizer rendering.

## QA grading and immutable final join

All respondent answers retain `passed_consequence_probe=None` in their original raw streams. Valid source answers produce the unchanged arm-blinded semantic-judge requests and separate private joins. Invalid source answers remain among all 40 source scenarios and do not produce invented judgments. `structured_records_worker` supports a 1–192-answer QA grading group so a valid tail of fewer than five answers need not be duplicated or omitted. Such a small group still has five fresh pilot trials with unique IDs, reusing source prompt content only in pilots. Other structured-record families retain a five-request minimum.

`exp11_evidence.complete_evidence(...)` requires all 26 action payloads, all 12 respondent payload/tokenizer pairs, and exactly the independent judgments reconstructed from valid source raw answers. It independently rechecks Phase 1 and Experiment 2.3 ordering, frozen sources, actual completed backend worker identity, central resource admission, every action trajectory, every respondent prompt, and both respondent and grader raw streams. It rejects duplicate, extra, missing, or changed grading requests.

The resulting `episodes` list is a separately hashed projection of all 4,520 original audited episode summaries. Each row references its original episode hash and actual same-arm/base consequence and rule scores; original raw data is untouched. The separate `probes` list has all 480 Boolean outcomes and detailed evidence references. These are the direct inputs to `exp11_binary_analysis.analyze` and the separately owned omnibus implementation. No effect estimates are computed by the worker or evidence adapter, and execution evidence never labels the full experiment or Phase 3 complete.

For final verification, `exp11_evidence.recompute(root, selection_path)` consumes an explicit immutable selection with schema `exp11_execution_selection_v1`, all `action_payload_paths`, twelve `respondent_items` containing `payload_path` and `tokenizer_path`, and all `judge_payload_paths`. Root must register this replay hook and the resulting statistical components in the final verifier before claiming a completed experiment. No selection file or empirical evidence result has been generated by this preparation work.
