# Phase 1 → Phase 2 automatic admission preparation

Prepared 2026-10-17 from the current specification's Phase 1 qualification/decoding gates, Experiment 2.3, Experiment 1.1, and phased execution table. No live launch, resource reservation, ledger modification, or primary partial-effect inspection was performed. This is a read-only preparation and independently audited ordering boundary. It does not submit jobs or authorize a full experiment by itself.

`phase2_admission.py` independently calls `phase1_readiness.recompute` on every invocation. It consumes an explicit component-selection JSON file, rejects out-of-sprint paths and changed selection bytes, and distinguishes incomplete Phase 1 evidence from a failed scientific/integrity gate. It never accepts a saved readiness Boolean as sufficient. All execution authorization fields remain false: the narrow ordering gate independently proves an actual Experiment 2.3 start but never replaces per-experiment design, resource admission or H5.

## Interfaces implemented

- `recompute(root, components_path, exp23_start_path=None)` returns independently recomputed Phase 1 status, scoped external eligibility, missing execution components, ordering state, and the exact author request plan. CLI: `.venv/bin/python scripts/phase2_admission.py --components <sprint-relative-selection.json>`. It prints JSON only; it does not persist files.
- `author_request_plan()` returns the existing fixed 48 unified-author requests plus five separately identified fresh pilots and a request-manifest digest. This is Role 2 stimulus preparation and never counts as the first empirical Phase 2 executor sweep.
- `record_request_batches(design)` partitions the design's exact pending requests into model-role/task/cot groups and deterministic batches of 5–192 requests. Balanced partitioning avoids a final 1–4-record remainder without duplication or padding. Too-small groups remain explicitly blocked. Requests are copied unchanged. Every batch requires a fresh five-trial pilot and independent upstream chain audit; no batch authorizes its own execution. Missing unified-author requests remain a separate list.
- `ordering_state(root, evidence_path=None, *, expected_readiness=None)` and `require_exp11_ordering(...)` call `audit_exp23_launch.recompute` every time, with no injected backend/tokenizer overrides or cached PASS. Evidence must identify the actual full executor ledger. The auditor reconstructs all five complete pilot episodes and their independent prompt/parser/sandbox audit, the distinct post-pilot full GPU call, backend identity/state, central resource reservation, exact CLI attempt/input selection, frozen payload/source bytes, Phase 1 prerequisites and completed stimulus sources. Optional `expected_readiness` must equal the selected source set in that payload. Success returns `EXP23_FIRST_FULL_CALL_VERIFIED` with its evidence hash and narrow audit; `require_exp11_ordering` raises `AdmissionBlocked` otherwise.

Experiment 1.1 respondent preparation, respondent execution and Modal batch authorization use the gate with their freshly recomputed Phase 1 readiness. Missing artifacts return WAITING; malformed/changed/failed evidence returns BLOCKED. Transport errors or temporarily absent backend call-graph evidence remain WAITING with overlap false. An uncommitted spawn intent is BLOCKED and must be reconciled without resubmission. Exact tokenizer-package mismatch is BLOCKED until the audit environment matches captured runtime metadata. Neither author nor structured-record jobs count as an empirical executor start.

## Scientific scope and prerequisite rules

Primary Phase 2 requires independently passing source-direction, post-FP8, six-checkpoint qualification, forty-scenario author audit, Intact calibration and complete five-alpha dose-response evidence, including cross-component provenance. A null or failing primary qualification/calibration result does not become a bypass; no threshold changes are implemented.

A failed external checkpoint-pair qualification excludes **only Role 1 external-validity comparisons** involving the Flash-Next/Uncensored pair. It does not remove the uncensored Role 2 unified author, which instead requires pinned download/runtime evidence and mechanical hygiene plus its own task pilot. It does not remove Llama, whose executor/judge roles require their own pinned runtime and task-specific pilots. External comparisons must never be pooled with primary arms. If external qualification later passes, the helper reports that a separately implemented slice is required; it does not claim that the current primary-only design has completed it.

Current `exp23_design.py` includes a hard-coded failed-external explanation. The admission helper does not trust that explanation as evidence: it derives scope from independent Phase 1 recomputation. If a new qualified external attempt is eventually selected, the design's separate external implementation must be added before claiming full scoped completion.

3. Recompute each author/structured raw-chain audit, exact request/return/prompt bindings, pinned model identities, H1/H5, and full source membership before combining bundles. Run the held-template masked-boilerplate check over all 48 paired scenarios. Freeze a combined dependency manifest and independently rebuild the executor request design. Reject wrong-role records, unreferenced evidence, duplicates and selected subsets; do not promote bundle metadata as an audit.
4. Root admits the first Experiment 2.3 executor pilot through the central bounded launcher. The prepared executor adapter supports the actual primary and Llama loaders, preserve six presentation orders, two authority levels, cot modes and all raw multi-turn prompt/return evidence. Separate semantic record labels from operational action outcomes.
5. After that executor's own five-trial pilot passes, durably commit its full-sweep admission. Independently audit the pilot and the post-pilot admission event against the exact payload/model/source hashes and central reservation. The pilot call must finish and independently pass before a separate full GPU call is spawned. A pre-pilot coordinator or pilot call ID cannot satisfy this gate.
6. Only then may independently frozen Experiment 1.1 action/probe work overlap Experiment 2.3. Its stimulus choices and grading protocol cannot depend on partially observed Experiment 2.3 effects. All six arms require action controls and both QA families; each sweep keeps its own fresh pilot. The QA judge protocol is separate from respondent execution and has its own H5.
7. Recompute complete experiment receipts and statistical outputs before any Phase 3 transition. Preserve the specified paired confidence-interval gate for Experiment 1.2; this helper never evaluates or bypasses it.

Root remains the single paid-launch authority. Every real future job needs an AST-validated resource profile, conservative GPU/CPU/time/call bounds, complete immutable read-dependency hashes, and central admission within the shared 10-GPU / $500 limits. Root's launch ledger and unique durable call intents govern crash recovery; observers must reattach existing jobs instead of resubmitting them. No independent local worker should assume these preparation manifests reserve resources.
