## Two separate paid calls, with a hard gate between them

1. Coordinator commits the immutable payload and `pilot.json` spawn intent, spawns exactly one pilot GPU call, then commits its concrete FunctionCall ID. The GPU wrapper waits at most 30 seconds for that exact actual call ID to be committed; it records the ID observed from inside the running function before inference.
2. Pilot GPU call completes five whole episodes, commits raw/journal/return/trajectory evidence and pilot Markdown, and returns its stage status. The coordinator waits for the call result, then independently re-renders its prompts and replays all five episodes from raw. A failed H5 prevents any full call.
3. Coordinator commits a **new** `full.json` spawn intent containing the completed pilot call ID, independently recomputed pilot-audit hash and pilot completion timestamp. Only then does it spawn and commit a separate full GPU call ID. Full worker independently rechecks the pilot before generation.
4. Existing committed stage calls are reattached by ID. An unresolved intent is never resubmitted. Stages claim their output paths exclusively; a duplicate worker cannot silently replace earlier evidence. A crash after a spawn but before its committed ID requires reconciliation, not automatic repeated spending.

The ordering auditor redoes Phase 1 readiness and the dependency-bundle audit, validates the five raw pilot episodes, exact pilot Markdown/status, actual pilot worker ID, separate full admission and chronology, root's matching resource/budget reservation, source profile and exact attempt. It queries both concrete FunctionCalls and requires the pilot to have succeeded and the full executor call to be pending/running or succeeded. Author or structured-record functions, failed calls, absent IDs and wrong modules cannot open the gate. Backend call-graph access is bounded to 60 seconds; Modal documents that graph capture can lag or be incomplete, so missing evidence fails closed and must be retried read-only.

## Evidence and independent reconstruction

Each stage has separate append-only hash chains for requests, pre-parser model returns, raw tool turns and derived episodes. A request commits before generation; all returned choices and prompt token IDs commit before parsing or shape assertions. Every trial retains its full original condition/authority/pairing/provenance metadata. All real assistant/tool-observation history is preserved. No completion prefix or truncation of input prompts is permitted; caps are 4096 for cot_on and 1024 for cot_off, with deterministic decoding and prefix caching disabled by the existing pinned loaders.

The independent stage auditor checks exact source requests, model identity, FP8 loaded inventory, output shape, every request→return→raw link, exact prompt text and token IDs against the captured tokenizer, and a separate implementation of all sandbox state transitions. It does not call the production `Sandbox.step` to determine expected outcomes. Full H1 requires both token-turn and episode truncation rates below 2%; H5 requires all five pilot episodes' tool decisions to be valid, closed when cot_on and uncapped. Failed/full malformed outcomes remain raw observations; they are not filtered into a successful sweep.

Producer-run input is an explicit ordered JSON list of `{kind: "author"|"structured", payload_path: "..."}` entries. The merged bundle must equal exactly all audited full producer records in that order. Each producer's complete chains, H1/H5, pinned identity and source files are verified before rebuilding the design. The unified-author runtime additionally binds its downloaded revision/preflight and independently reproduced mechanical qualification; a failed Role 1 refusal gap does not disqualify Role 2 authorship. Exact equality of all 48 harmful/harmless scaffolds after telemetry masking is checked and recorded; this equality implies chance prediction from balanced paired boilerplate, rather than claiming an unrun classifier fit.
