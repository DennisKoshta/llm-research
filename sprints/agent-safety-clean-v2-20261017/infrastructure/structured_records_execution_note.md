# Structured-record execution infrastructure

Prepared, tested offline, and not launched. No reviewer memo, paraphrase, semantic verdict, QA judgment, Phase 2 observation, or empirical result was generated by this work.

## Files and interfaces

- `scripts/structured_records_worker.py`: strict request admission, recursive typed-record validation, five fresh pilots, inference/evidence pipeline, and `audit_streams(root, payload)`.
- `scripts/modal_structured_records.py`: bounded Modal packaging and `prepare(root, attempt, requests_path, components_path, *, tokenizer_metadata)`. Preparation independently recomputes `phase1_readiness.recompute`; the entrypoint defaults to `launch=False`. Root remains the sole paid launcher and resource/budget coordinator.
- `scripts/llama_model_loader.py`: reuses the exact current-sprint Llama header inventory, named FP8 RPC, model loader parameters, and reasoning header from the serving pilot. Existing loaders/runners were not edited.
- `scripts/structured_records_evidence.py`: independent completed backend-call, central-admission, and exact tokenizer/prompt replay added after independent review.
- `tests/test_structured_records_execution.py`: 14 focused offline tests pass; separate evidence-boundary tests exercise the strengthened complete audit. Fixtures exist only in temporary directories beneath `tests/` and are deleted afterward.

`requests_path` is a frozen JSON array containing exactly one role, task, and reasoning mode. Its bytes and parsed requests are both checked. A full request group contains 5–192 requests, except independent QA grading permits 1–192 existing valid-source judgments. Five fresh trials are regenerated under unique pilot IDs before the full group; fewer than five valid QA sources repeat source content in pilots only, never duplicate evaluation judgments; old pilot outputs are never reused. Groups larger than 192 require explicit separate immutable attempts, each with its own pilot. Every request retains its original ID, messages, declared tool, schema, temperature, rollout count, cap, and provenance. Caps must be integers from 4096–8192 for `cot_on`, or 1024–8192 for `cot_off`; lower defaults cannot enter this interface.

The supported natural reviewer roles map only to the Intact, PCA-101, and Refusal-Ablated current-sprint full-residual checkpoints. The immutable materialization-manifest SHA-256 is their `model_revision`; their base source revision is separately preserved. Runtime verifies all materialization shards against hashes before loading, then verifies the exact primary FP8 module inventory through the existing loader.

Llama paraphrasing, semantic judgments, and QA grading map only to `nvidia/Llama-3.3-70B-Instruct-FP8` at `fde04ee76a27704c88f569542ef023b57d4d0362`. Download/preflight evidence, all pinned metadata and tensor headers, and the named loaded-module RPC are checked. As in the proven pilot, full Llama tensor payload bytes are **not** independently hashed; the stored audit scope says this explicitly.

## Admission and concurrency

Before preparation can produce a payload, independent source/post-FP8/primary/author/calibration/dose audits and their aggregate provenance must pass. A failed or absent external-pair qualification does not block primary record work. The complete readiness object, required receipt hashes, aggregate provenance hashes, request-file hash, specification hash, exact tokenizer files/source paths, component selection, and packaged runtime source hashes are frozen in the payload and checked remotely. A recursive local import-source closure and read hook bind supplemental auditors even if their imports were previously cached. Only global mutable budget/resource ledgers are excluded from scientific source freezing; their relevant exact admissions are separately verified. Readiness is a prerequisite only; it is not evidence that Phase 2 or the full program is complete.

One Modal app permits at most two single-H200 workers, each with four CPUs, 64 GiB memory, 3600-second execution and 300-second startup limits, and zero retries. Root must also enforce the global budget/resource cap across apps. The new `resource_config(root, payload, input_path)` declares exactly one GPU call and one coordinator; the local `--attempt/--input-path/--launch` entrypoint requires the matching central reservation, exact CLI values and canonical `stimuli/<experiment>_input.json`, plus independent Phase1 reconstruction, before submission. Each worker uses an attempt-specific local compiler cache. No TP8 path exists. The CPU coordinator durably writes `SPAWN_INTENT` before spawning, then preserves the actual call ID; interrupted intents fail closed and cannot silently resubmit. A worker waits at most ten seconds for its exact committed call ID before any model initialization. The actual worker compares that ID to `modal.current_function_call_id()` and persists `structured_worker_starts/<experiment>.json` before model loading. Reattachment uses that existing ID. Root must never submit the same attempt through concurrent coordinator invocations; Modal volumes are not a distributed compare-and-swap service.

Each output path includes attempt, role, task, and reasoning mode. An exclusive writer claim binds the payload and durable call ledger. Completed/failed attempts are immutable; recovery requires read-only reconciliation, or a separately named, reviewed attempt.

## Evidence and semantics

For experiment ID `structured_<attempt>_<role>_<task>_<mode>`, persist:

- canonical `stimuli/<experiment>_input.json`, its remote `structured_inputs/<experiment>.json` copy, `group_calls/<experiment>.json`, and `structured_worker_starts/<experiment>.json`;
- `raw_transcripts/<experiment>/<role>.jsonl`, `<role>_requests.jsonl`, `frozen_input.json`, `attempt_claim.json`, `loaded_model_inventory.json`, `runtime_context.json`, and exact copied tokenizer files under `tokenizer/`;
- `structured_artifacts/<experiment>/model_returns.jsonl`;
- `pilots/<experiment>_pilot_audit.md` and `qualification_status/<experiment>.json`;
- `structured_artifacts/<experiment>_bundle.json` only when the entire fixed full group passes mechanical/typed-record gates.

Writeahead records and exact prompt token IDs are committed before inference. Every returned completion is committed in a separate hash chain before parsing, shape assertions, or token-identity assertions. Canonical raw rows bind both chains. Full prompt text, logical `messages`, actual `rendered_messages`, all generated token IDs, finish reason, parser fields, model identity, and source/request hashes remain inspectable. Llama's required reasoning header is added only to `rendered_messages`; logical `messages` remain byte-equivalent to the upstream Exp2.3/QA request. Runtime-returned prompt token IDs must equal the frozen input sequence. `structured_records_evidence.audit_complete_run` additionally reconstructs the model-specific rendered prompt and token IDs from the captured tokenizer bytes under identical transformers/tokenizers/Jinja2 versions, verifies the actual successful backend worker identity and central admission, and rechecks source bytes. This stronger complete audit is required before final Exp1.1 QA inclusion or Exp2.3 dependency adoption; lower `audit_streams` is only the raw-chain/parser component.

The independent JSON decoder refuses unclosed `cot_on` reasoning, duplicate keys, nonfinite literals, multiple blocks, extra envelope fields, and schema violations. Supported schema constraints are checked recursively; unknown constraints fail closed. Every pilot requires five valid uncapped records with parser agreement and closed reasoning where applicable. Full sweeps require strictly less than 2% logical truncation (capping or missing closed reasoning), complete raw coverage, and valid records for every requested artifact. Malformed outputs are retained and cannot be filtered into a partial successful bundle.

Boolean `false` judgments are valid scientific evidence. This worker does not infer semantic acceptance, rewrite claims, select recommendations, or classify downstream behavior. The four-way raw outcome field is explicitly scoped to **record validity only**, never an executor action. Raw bundles are directly compatible with `exp23_design.read_artifact`; QA judge requests and full outputs pass the repaired `qa_semantic_protocol` API. QA private joins/source manifests never enter the judge request payload.

These jobs always declare `phase2_executor_launch=False`. They cannot satisfy the required first Exp2.3 full executor launch, unlock overlapping Exp1.1, authorize Phase 3, or establish any statistical result. Respondent QA probes and operational executor episodes require separate runners and admission.

## Offline verification

The focused worker tests cover Exp2.3 artifact compatibility; actual QA protocol request/score compatibility; false judgments; separate `cot_off` pilots; unclosed-pilot stopping; malformed full-record retention; nested schema constraints; request/model/prerequisite mutation; returned-shape/token mismatch preservation; exclusive attempts; raw-chain and loaded-inventory tampering; missing durable-call rejection; and the actual coordinator's reattachment/unresolved-intent behavior. No Modal deployment, remote call, or GPU inference was used to run these tests.
