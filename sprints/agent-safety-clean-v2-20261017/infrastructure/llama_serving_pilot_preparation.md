# Llama cross-family stack pilot preparation

**Prepared, GPU execution untested. No pilot pass or downstream scientific result is claimed.**

The new self-contained runner is `scripts/modal_llama_serving_pilot.py`; its GPU worker and named inventory RPC are in `scripts/llama_serving_worker.py`. It requests one H200, four bounded CPU cores and 64 GiB RAM, with a 1,800-second execution timeout plus 300-second startup timeout. The CPU coordinator has a durable payload-hash/call-ID ledger and a 3,600-second timeout. No existing runtime files were changed.

The pinned repository is `nvidia/Llama-3.3-70B-Instruct-FP8`, revision `fde04ee76a27704c88f569542ef023b57d4d0362`, at `/weights/agent-safety-clean-v2-20261017/source_models/nvidia__Llama-3.3-70B-Instruct-FP8`. Read-only inspection of this namespace established an 80-layer Llama architecture, 15 shards, 2,003 indexed tensors and 72,656,376,832 tensor payload bytes. `hf_quant_config.json` declares ModelOpt 0.27.1, FP8 weights and FP8 KV scaling, with `lm_head` excluded. The first shard's 9,360-byte header confirms F8_E4M3 weights and F32 scales; the volume client transferred one 8 MiB chunk to obtain that header. No model was downloaded again or GPU job launched.

Metadata SHA-256 values are frozen in the worker. At runtime it will inspect all shard headers, require exact index coverage, derive the expected seven quantized projection matrices per layer from the actual architecture, and verify FP8 scales and BF16 excluded weights. A Llama-specific named worker RPC will compare the actual loaded FP8 modules with the mapped/fused header inventory. It does not reuse the primary model's 400-module assertion. The expected architectural inventory is 560 unfused projections and 320 fused runtime modules; GPU execution must establish the actual matching set before generation. Header inspection is not a full independent checksum of tensor payload bytes, which is stated in the saved inventory.

The runtime uses stock `vllm/vllm-openai:v0.31.0`, `quantization='modelopt'`, FP8 KV cache, eager loading/execution, prefix caching disabled, greedy decoding, one GPU, five maximum simultaneous sequences and a 16,384-token context. vLLM's published implementation supports the ModelOpt configuration and reads `hf_quant_config.json`; the Llama implementation provides its projection mapper and packed-module mapping. Sources: [ModelOpt quantization implementation](https://raw.githubusercontent.com/vllm-project/vllm/v0.31.0/vllm/model_executor/layers/quantization/modelopt.py), [Llama implementation](https://raw.githubusercontent.com/vllm-project/vllm/v0.31.0/vllm/model_executor/models/llama.py).

The worker uses the five fixed `stimuli/phase1_pilot.jsonl` requests, with a 4,096-token completion allowance. A system instruction asks Llama to produce and close its own reasoning block before a strict JSON tool call. Its native chat template supplies only the ordinary assistant-role header; no assistant completion text or forced prefix is appended. Both rendered prompt text and exact prompt token IDs are persisted; generation receives those token IDs to avoid duplicate automatic special tokens. Missing `</think>` remains `TRUNCATED_IN_THINK`, with no fallback parsing.

Outputs are isolated under `raw_transcripts/phase1_llama_serving_<attempt>/`, with a write-ahead request journal, all five raw completions, `pilots/phase1_llama_serving_<attempt>_llama_intact_pilot_audit.md`, serialized and loaded inventories, and `qualification_status/llama_serving_<attempt>_llama_intact.json`. Artifact commits require acknowledgement before generation proceeds. Existing attempt evidence cannot be silently overwritten; engineering failures and failed pilots remain failures. This is Phase 1 stack readiness only and cannot launch Phase 2 or Phase 3.

Validation completed locally: Python compilation, isolated runner import without sibling runner dependencies, three CPU-only contract tests covering unclosed reasoning, absence of assistant prefixes and architecture-derived serialized FP8 coverage, and resource-profile parsing. Actual GPU loading, named RPC execution, memory fit and model compliance with the reasoning protocol remain untested.
