# Exp1.1 respondent QA engine and integration plan

Prepared and tested offline; no respondent answer, judge output, Modal application, or GPU job was generated by this work. The respondent engine is now packaged in `scripts/modal_exp11_evaluation.py`; see `infrastructure/exp11_execution_note.md` for the tested bounded action/QA integration. `scripts/exp11_probe_worker.py` and its nine tests are new files; the existing scientific design, loaders, observers, and receipts were not edited.

## Implemented boundary

`prepare_group(root, attempt, arm, kind, *, bases_path, design_path, components_path, ordering_evidence_path)` independently recomputes primary Phase1 readiness and the real first-Exp2.3 executor launch requirement. It reconstructs all forty bases from unified-author raw evidence and verifies the complete saved Exp1.1 design. It returns an immutable payload only after these checks. `phase2_admission.require_exp11_ordering` now independently replays the real Experiment 2.3 executor pilot and checks its actual subsequent full-sweep backend call, with the same selected Phase 1 sources. Caller flags, author jobs, and structured-record jobs cannot bypass this boundary.

`run_admitted(root, payload, commit)` repeats those audits before model loading, checks source bytes, reconstructs the author/design sources, hashes exact model shards, and uses only the current-sprint primary loader. No model-loader callback or alternate checkpoint mapping is accepted. The loaded FP8 inventory and tokenizer metadata hashes are persisted before any generation. The bounded Modal wrapper performs the independent readiness and ordering checks at local admission, then repeats exact frozen-byte and model checks remotely; this module cannot provision a GPU itself.

Twelve groups cover all six primary checkpoints and both `consequence_awareness` and `rule_identification`. Each has exactly forty fixed `cot_on` answers at the existing 4096 cap and five fresh pilots from source indices 0, 8, 16, 24, 32. This adds thirty pilot-only generations relative to the design's original combined QA pilot grouping; it changes no evaluation trial, denominator, or prompt. IDs, paired prompts, factual references, operational registry, and source-arm mappings come directly from `exp11_design`. Each tool call only records a factual response. No sandbox step or operational tool invocation is possible.

Before each inference, `qa_semantic_protocol.make_source_manifest` freezes the actual rendered prompt/token sequence, tokenizer metadata hashes, source author base, complete design hash, and pinned materialized checkpoint identity in the durable writeahead record. Every raw model return is separately committed before parsing. Raw, writeahead, and return streams are chained to the immutable payload and linked to each other. Pilot source manifests reference the corresponding fixed evaluation source; pilots have distinct trial IDs and never become scientific estimates or judge requests.

Raw output paths use `exp11_probe_<attempt>_<arm>_<kind>_cot_on` and cannot collide with action or independent-grader streams. `raw_transcripts/<experiment>/<arm>.jsonl` retains all responses; `probe_artifacts/<experiment>/model_returns.jsonl` retains pre-parser returns. The attempt claim, frozen input, loaded inventory, pilot audit, and status follow the same current-sprint layout as the structured-record runner. Root's future coordinator must commit `group_calls/<experiment>.json` with state `SPAWNED`, actual call ID, exact payload hash, and experiment ID before this engine starts.

## Grading and the analysis interface

Passing mechanical gates produces all forty full raw rows, a separate `*_private_joins.json`, and a public `*_grading_requests.json`. Invalid answers remain in the fixed denominator and produce explicit invalid-source joins; the worker never invents a judgment for them, drops them from the source bundle, or retries them for a preferred answer. Valid answers with incorrect typed facts still receive their normal semantic judgment. The independent grader sees only the unchanged arm-blinded protocol requests.

`scored_probe_rows(root, respondent_payload, judge_payloads)` independently audits the respondent stream and every supplied grader stream, including both sets of five fresh pilots. It reconstructs every private join from source raw evidence, rejects duplicate or missing required judgments, and returns exactly forty rows containing:

- `scenario_id`, `model_arm`, `probe_kind`, and Boolean `passed`;
- source-validity and judge-validity fields, raw/source-manifest/audit hashes;
- the two existing high-cost action pairing IDs for each cost-invariant consequence probe.

Invalid source answers count as not demonstrating awareness. A missing required valid-source judgment blocks scoring; it is never silently labeled false or true. Scientific paired conditioning belongs to the independent analysis layer: both arms must pass their probes for the common-scenario paired estimand; arm-specific conditional descriptions retain separate denominators. This engine performs no behavioral comparison or statistical test.
