# Independent Exp1.1 execution review

Scope: prepared action/coordinator/admission/evidence code, immutable QA joins, source identities, resource bounds and binary/omnibus input compatibility. No research outcomes were inspected and no jobs were launched. All `test_exp11_*` tests passed: 55 tests in 66.3 seconds before the additional structured-grader repairs below.

## Checks supported by code and synthetic tests

- Fixed all-six-arm execution covers 26 action chunks (4,520 full episodes) and 12 respondent groups (480 full answers), with five fresh pilots per chunk/group. Aggregation requires every registered key exactly once and rejects selected or duplicate groups.
- Action generation persists each prompt/token request before inference and every returned batch before parsing. Independent replay reconstructs full history and sandbox state. Both turn-level and episode-level H1 use the union of token caps and unclosed reasoning; cap-only source counters are retained separately.
- Respondent manifests bind original authored scenario, exact probe, arm/checkpoint identity, rendered prompt, token IDs and tokenizer hashes before generation. QA scoring reconstructs private joins rather than accepting cached joins. The scored episode projection is separate from original raw episodes and retains hashes of its source episode and both probe scores.
- Actions and respondents capture their actual Modal FunctionCall ID. Final evidence verifies backend function/module/success and exact central CLI, payload/source bindings and declared calls. The whole app permits at most two single-H200 item calls, one bounded CPU coordinator, no retries and no hidden child GPU calls.
- The raw-derived episode fields satisfy the binary and omnibus input contracts. The binary analysis retains malformed observations in ITT and uses common valid pairs for strict estimates. The omnibus selects the registered 2,880 cot_on main-grid episodes only after requiring all 4,520 action episodes.

## Findings and repair ownership

1. **Independent grader actual execution provenance was weaker than respondent provenance.** The old structured worker accepted a ledger's claimed call ID without comparing it to its actual Modal call; complete QA evidence did not independently check grader backend identity or central admission. The owner added actual worker-start capture and immutable central admission, including a regression proving a mismatched current Modal call never starts a subprocess. New `scripts/structured_records_evidence.py` independently checks canonical input, exact CLI arguments, frozen sources, one GPU/one coordinator call, source-recomputed Phase1, exact start marker and successful `records` backend identity.
2. **Independent grader prompt replay was incomplete.** Its old audit compared raw prompts/tokens to writeahead and model returns but did not reconstruct them from captured tokenizer bytes. The owner added tokenizer source/capture/runtime metadata and requires the strong complete audit for every final grader. The new evidence auditor verifies exact library versions by default and independently renders every pilot/full prompt and token sequence before adoption. Eight focused tests pass, including changed tokenizer bytes, wrong rendering, wrong backend/start, changed Phase1, swapped central input and invalid completion status.
3. **Action H5 may reject the scientific target in the unlisted-shortcut control.** A closed, syntactically valid tool JSON invoking the deliberately unlisted shortcut is classified `UNDECLARED_TOOL`; the current action pilot requires `VALID`, so the full chunk can be blocked by the behavior it is meant to measure even when both parsers agree. The fixed final-chunk pilot includes one unlisted-shortcut case. The owner repaired this with root agreement: an independent JSON envelope parser must agree exactly on name/arguments for either VALID or UNDECLARED_TOOL, with closed reasoning and no capping. Undeclared calls remain malformed observations and are never executed. A regression now emits the unlisted target during the pilot and verifies H5 passes without changing its taxonomy. No parser or scenario source was edited by the reviewer.
4. **Historical reservation validation must distinguish original admission from later reconciliation.** Central audits currently feed the current budget reservation into the original profile validator. The stopped-job reconciler can legitimately reduce that reservation, making a later historical raw audit fail even though initial admission was sufficient. Root added the original `admitted_upper_bound_usd` to both new allocation and reservation rows. New `historical_admission.py` validates equal positive originals, the chronological per-job nonincreasing reconciliation chain and exact final current amount, then validates the resource profile using the original amount. Six focused tests pass. Structured and Exp1.1 fresh-launch admission additionally reject already-reconciled funding. Historical audit output stays stable after valid reductions, preserving scientific source identities; no legacy-field fallback or ledger mutation is used.

The stronger structured evidence audit is also wired into `audit_exp23_launch.dependency_bundle`. It binds each upstream structured worker start, exact call ledger, runtime context, status and captured tokenizer files. `modal_exp23_executor.prepare` excludes only the two mutable global resource/budget ledgers from file freezing; the selected central row and profile remain independently reconstructed. Live unified-author runtime files were not changed.
